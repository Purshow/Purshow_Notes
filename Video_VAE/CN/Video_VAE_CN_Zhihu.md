# 拆解视频 VAE：从 Wan 到 H3、LTX 和 FLUX，看懂压缩、解码与 DiT token

看视频生成模型时，我们经常会看到这样的描述：

> VAE 的压缩倍率是 4×16×16，latent 有 48 个通道。

但真正开始算显存、看代码或者对齐张量形状时，问题才出现：

- 时间压缩 4 倍，为什么 81 帧会变成 21 个 latent 时间位置？
- 空间压缩倍率相同，送进 DiT 的 token 数为什么还能差 4 倍？
- Encoder 是因果结构，是否意味着 Decoder 也能逐帧独立执行？
- 都叫 VAE，为什么有的靠卷积恢复视频，有的用 Transformer，甚至还要做一次像素去噪？

要回答这些问题，光看压缩倍率还不够。需要把一段视频从输入、编码、latent，一直跟到解码和像素重建。

这篇文章以 **81 帧、480×832 的 RGB 视频**为统一例子，重点拆解 Wan2.1、MiniMax H3、LTX-2.5 和 FLUX 3 的 VAE，并对比 Wan2.2、HunyuanVideo-1.5 与 MAGI-2 Preview。关注点是具体结构和 forward 过程，不做画质排名。

如果只想先看整体差异，可以读第 1 节；想理解因果卷积和历史缓存，可以从第 2 节的 Wan2.1 入手；后面三节分别讨论 H3 的窗口解码、LTX 的两种 Decoder，以及 FLUX 的邻域注意力。

下文的压缩倍率统一按**时间 × 高度 × 宽度**排列。逐层形状统一写作 `[C,T,H,W]`，省略 batch 维；涉及 DiT 输入时再显式写出 `B`。各项参数对应文中所列模型配置。

## 1. 先分清：压缩倍率、元素压缩比和 token 数

### 1.1 压缩了多少空间位置，还要看保留了多少通道

设输入视频形状为 `[B,3,T,H,W]`，VAE 输出为 `[B,C,T_z,H_z,W_z]`。时间、高度和宽度的压缩倍率分别为 $r_t,r_h,r_w$。

忽略首帧和边界处理时，标称元素压缩比为：

$$
R_{\mathrm{nom}}=\frac{3r_t r_h r_w}{C}.
$$

这里比较的是**张量中的标量元素数**。它不等于视频文件的编码压缩率；如果输入和 latent 的存储精度不同，也不能直接当作字节数之比。

对于一段具体的视频，应按实际 latent 形状计算：

$$
R_{\mathrm{actual}}=\frac{3THW}{C\,T_zH_zW_z}.
$$

下面先把各模型的参数放在一起。为方便阅读，第一列按 VAE 或对应模型简称排列。

| VAE / 对应模型 | 时间 × 高 × 宽压缩 | Latent 通道 C | 标称元素压缩比 |
|---|---|---:|---:|
| Wan2.1-VAE | 4×8×8 | 16 | 48:1 |
| Wan2.2-VAE | 4×16×16 | 48 | 64:1 |
| HunyuanVideo-1.5 | 4×16×16 | 32 | 96:1 |
| MAGI-2 Preview | 4×16×16 | 48 | 64:1 |
| H3-VisualVAE | 4×16×16（标称） | 24 | 128:1（标称） |
| LTX-2.5 Video VAE | 8×32×32 | 128 | 192:1 |
| FLUX 3 Video VAE | 4×32×32 | 96 | 128:1 |

这里有两个容易混淆的版本关系：**Wan 2.1、Wan 2.2 A14B 和 Lingbot-Video 使用的是 Wan2.1-VAE；Wan 2.2 TI2V-5B 使用的是 Wan2.2-VAE。**MAGI-2 Preview 则采用 Wan2.2-VAE 编码器，并配合 TurboVAED 蒸馏解码器。

**H3 的“时间压缩 4 倍”尤其需要单独看。**它涉及 17 帧编码块、latent 裁剪和重叠窗口解码，不能把整段输入长度直接除以 4。第 3 节会完整追踪这条路径。

### 1.2 为什么 81 帧压缩 4 倍，会得到 21 个时间位置？

对于采用首帧对齐规则、且长度满足对齐要求的配置，常见的时间关系是：

$$
T_z=1+\frac{T-1}{r_t}.
$$

因此，时间压缩倍率为 4 时：

$$
81=1+20\times4
\quad\Longrightarrow\quad
T_z=21.
$$

时间压缩倍率为 8 时，则有：

$$
81=1+10\times8
\quad\Longrightarrow\quad
T_z=11.
$$

这个公式描述的是**输入和输出的长度关系**。至于执行时是首帧单独处理、逐层保留缓存，还是整段执行后再做边界裁剪，需要继续看实现。不能由这个公式直接推出“每个 latent 时间位置都能独立解码”。

首帧处理也解释了为什么标称元素压缩比和实际值存在差别。例如，Wan2.1 在本文尺寸下的实际元素压缩比约为 46.29:1，而不是恰好 48:1。

### 1.3 DiT 的 patchify 还会改变 token 数

VAE 输出之后，DiT 可能继续做一次 patchify。若 patch 大小为 $p_t\times p_h\times p_w$，对齐后的视觉 token 数为：

$$
N=\frac{T_zH_zW_z}{p_tp_hp_w}.
$$

Patchify 后、线性投影前，每个 token 包含的特征数为：

$$
D_{\mathrm{patch}}=C\,p_tp_hp_w.
$$

也就是说，patchify 将局部位置合并到特征维，减少 token 数，但这一步重排本身不减少元素总数。这里的 $D_{\mathrm{patch}}$ 也不是 DiT 投影后的隐藏维度。

以本文的 81 帧、480×832 输入为例：

| VAE / 对应模型 | DiT patch | Patchify 后、投影前的网格形状 | 视觉 token 数 |
|---|---|---|---:|
| Wan2.1-VAE | 1×2×2 | `[B,64,21,30,52]` | 32,760 |
| Wan2.2-VAE | 1×2×2 | `[B,192,21,15,26]` | 8,190 |
| HunyuanVideo-1.5 | 1×1×1 | `[B,32,21,30,52]` | 32,760 |
| MAGI-2 Preview | 1×1×1 | `[B,48,21,30,52]` | 32,760 |
| H3-VisualVAE | 1×2×2 | `[B,96,27,15,26]` | 10,530 |
| LTX-2.5 Video VAE | 1×1×1 | `[B,128,11,15,26]` | 4,290 |
| FLUX 3 Video VAE | 1×1×1 | `[B,96,21,15,26]` | 8,190 |

H3 这一行先将 81 帧补到 90 帧，再按其分块规则编码。表中的网格形状还没有展平成 `[B,N,D_patch]`。以上只统计由视频 latent 得到的视觉 token，不包含文本等其他 token。

一个直接的对比是：Wan2.2-VAE 和 HunyuanVideo-1.5 都采用 4×16×16 的 VAE 压缩倍率，但前者还会做 1×2×2 的 DiT patchify，因此在这个例子中，视觉 token 数只有后者的四分之一。

反过来，latent 通道更少，也不必然意味着 token 更少。比较计算开销时，还要继续看 DiT 的隐藏维度、网络深度和注意力实现。

另一个边界是：VAE 内部的 patchify 已经包含在 VAE 压缩倍率中，计算压缩比时不要再乘一次。

## 2. Wan2.1-VAE：先看懂因果卷积和历史缓存

先从 Wan2.1-VAE 开始。它采用因果 3D CNN Encoder 和因果 3D CNN Decoder，适合用来理解视频 VAE 的时间压缩、首帧处理和逐层缓存。

以 **81 帧、480×832** 的 RGB 视频为例：

**整段视频：**`[3,81,480,832]` → **latent：**`[16,21,60,104]` → **重建视频：**`[3,81,480,832]`。

$$
T_z=1+\frac{81-1}{4}=21,\qquad H_z=\frac{480}{8}=60,\qquad W_z=\frac{832}{8}=104.
$$

### 2.1 Encoder：跟踪后续的 4 帧视频块

整段视频按 **1、4、4……帧**分成 **21 个块**：1 个首帧块，加上 20 个后续块。

这些块通过逐层的 Feature Cache 传递历史特征，后续块的计算会用到之前留下的状态。下面跟踪一个后续 4 帧块的 forward 过程：

| 顺序 | 模块与操作 | 输出形状 |
|---|---|---|
| 输入 | 当前视频块 | `[3,4,480,832]` |
| 入口 | 因果卷积 **3→96** | `[96,4,480,832]` |
| 第一级 | 残差块 ×2，输出 96 通道 → **空间下采样** | `[96,4,240,416]` |
| 第二级 | 残差块 ×2，输出 192 通道 → **时空下采样** | `[192,2,120,208]` |
| 第三级 | 残差块 ×2，输出 384 通道 → **时空下采样** | `[384,1,60,104]` |
| 第四级 | 残差块 ×2，输出 384 通道 | `[384,1,60,104]` |
| 瓶颈 | 残差块 → 空间 Attention → 残差块 | `[384,1,60,104]` |
| 出口 | RMSNorm → SiLU → 因果卷积 **384→32** | `[32,1,60,104]` |

全部 21 个块编码完成后，先沿时间维拼接，经过一个 `1×1×1` 卷积，再拆分为 $\mu$ 和 `log_var`，各为 `[16,21,60,104]`，对 $\mu$ 按通道标准化后，作为后续生成模型的输入。

### 2.2 Decoder：跟踪后续的 latent 时间步

先对完整 latent **撤销标准化**，经过 **`1×1×1` 卷积，16→16**，形状仍为 `[16,21,60,104]`。随后逐个 latent 时间位置解码；下表跟踪一个后续时间步：

| 顺序 | 模块与操作 | 输出形状 |
|---|---|---|
| 输入 | 撤销标准化后的 latent 块 | `[16,1,60,104]` |
| 入口 | 因果卷积 **16→384** | `[384,1,60,104]` |
| 瓶颈 | 残差块 → 空间 Attention → 残差块 | `[384,1,60,104]` |
| 第一级 | 残差块 ×3，输出 384 通道 → **时空上采样，384→192** | `[192,2,120,208]` |
| 第二级 | 残差块 ×3，先将 **192 升至 384** → **时空上采样，384→192** | `[192,4,240,416]` |
| 第三级 | 残差块 ×3，输出 192 通道 → **空间上采样，192→96** | `[96,4,480,832]` |
| 第四级 | 残差块 ×3，输出 96 通道 | `[96,4,480,832]` |
| 出口 | RMSNorm → SiLU → 因果卷积 **96→3** | `[3,4,480,832]` |

其中，首帧会跳过时间重采样，只输出 **1 帧**。

### 2.3 上下采样

| 操作 | 具体实现 | 形状变化 |
|---|---|---|
| **空间下采样** | 逐帧右侧、下侧补 1 → `3×3 Conv2d`，`stride=2` | $H,W$ 各减半；$C,T$ 不变 |
| **时间下采样** | 拼接 **1 帧历史缓存** → `3×1×1` 时间卷积，时间步长 2 | 后续块 $T$ 减半；$C,H,W$ 不变 |
| **空间上采样** | 逐帧最近邻插值 ×2（`nearest-exact`）→ `3×3 Conv2d`，$C\rightarrow C/2$ | $H,W$ 各翻倍，$C$ 减半；$T$ 不变 |
| **时间上采样** | `3×1×1` 因果卷积，$C\rightarrow2C$ → 将两组通道重排到时间维 | 后续块 $T$ 翻倍；最终 $C,H,W$ 不变 |

**执行顺序：**时空下采样是 **先空间、后时间**；时空上采样是 **先时间、后空间**。

#### 残差块、缓存与 Attention

- **残差块：**主分支执行两组“RMSNorm → SiLU → `3×3×3` 因果卷积”，再加 shortcut；通道不同时，shortcut 通过 `1×1×1` 卷积对齐。残差块保持 $T,H,W$。
- **因果卷积缓存：**普通时间核为 3、步长为 1 的因果卷积，需要前 **2 个时间位置**的特征；序列开头不足处补零。缓存由各层分别维护，时间位置以该层分辨率为准。上表时间下采样使用的是单独的 **1 帧缓存**路径。
- **帧内空间 Attention：**只在同一时间位置的二维特征图上计算，保持 `[C,T,H,W]`；跨时间的信息通过因果卷积传递。

### 2.4 Wan2.2、HunyuanVideo-1.5 和 MAGI-2 改了什么？

有了 Wan2.1 的结构，再看其他模型时，可以重点比较压缩倍率、采样模块和 Attention 的作用范围。

**Wan2.2-VAE** 延续了 Wan2.1-VAE 的因果卷积和 $4n+1$ 处理方式，时间压缩倍率仍为 4。主要变化是入口新增 `2×2` patchify，将空间位置重排到通道维，再经过三次空间下采样，使空间压缩从 8×8 提升到 16×16，同时将 latent 通道数从 16 增加到 48。结构上，Wan2.2 加宽了编码器和解码器：编码器基础通道数从 96 增至 160，瓶颈通道数从 384 增至 640；解码器基础通道数从 96 增至 256，瓶颈通道数从 384 增至 1024。同时，在原有残差块之外，为整个采样级增加 shortcut：下采样通过重排与 Avgpool 对齐形状，上采样通过重排与复制对齐形状，再与主分支相加。

**HunyuanVideo-1.5** 使用 AutoencoderKLConv3D，保持 4× 时间压缩，将空间高宽各自的压缩倍率从 8× 提高到 16×，latent channels 从 16 增至 32。相比 Wan 的分离式时空采样，它采用 causal convolution 加 PixelShuffle/Unshuffle 式重排，并在采样模块和 latent 两端的投影中增加 residual shortcuts。中间 Attention 则从帧内的 spatial attention 扩展为 spatiotemporal causal attention，能够直接关注当前及历史帧，实现跨帧信息交互。

**MAGI-2 Preview** 使用 Wan2.2-VAE 的因果 3D CNN Encoder，并配合 TurboVAED 非因果 3D CNN 蒸馏 Decoder。它保留 4×16×16 的压缩倍率和 48 个 latent 通道；文中配置的 DiT patch 为 1×1×1，因此不能直接沿用 Wan 2.2 TI2V-5B 的 token 数。

## 3. MiniMax H3：为什么不能直接把时间长度除以 4？

H3-VisualVAE 采用因果 3D CNN Encoder 和非因果 ViT Decoder。它与前面最明显的区别，在于时间分块和解码方式。

MiniMax H3 的默认视频分块规则要求长度对齐到 **$17n+5$**。这个实现行为可以沿着张量形状追踪，但不能仅凭分块规则确定其设计动机。

如果原视频是 **81 帧**，本例先**复制末帧补到 90 帧**，重建后裁掉末尾 9 帧。

**整段视频：**`[3,90,480,832]` → **latent：**`[24,27,30,52]` → **重建视频：**`[3,90,480,832]`。

$$
90=17\times5+5,\qquad T_z=5\times5+2=27,\qquad H_z=\frac{480}{16}=30,\qquad W_z=\frac{832}{16}=52.
$$

### 3.1 Encoder：跟踪一个 17 帧视频块

编码时，90 帧还会在内部复制末帧，临时补到 **102 帧**，再分成 **6 个 17 帧块**独立编码。

| 顺序 | 模块与操作 | 输出形状 |
|---|---|---|
| 输入 | 当前视频块 | `[3,17,480,832]` |
| 入口 | `3×3×3` 因果卷积，**3→128** | `[128,17,480,832]` |
| 第一级 | 残差块 ×2，输出 128 通道 → **空间下采样** | `[128,17,240,416]` |
| 第二级 | 残差块 ×2，输出 256 通道 → **时空下采样** | `[256,9,120,208]` |
| 第三级 | 残差块 ×2，输出 256 通道 → **时空下采样** | `[256,5,60,104]` |
| 第四级 | 残差块 ×2，输出 512 通道 → **空间下采样** | `[512,5,30,52]` |
| 第五级 | 残差块 ×2，输出 512 通道 | `[512,5,30,52]` |
| 第六级 | 残差块 ×2，输出 1024 通道 | `[1024,5,30,52]` |
| 出口 | GroupNorm → SiLU → 因果卷积，**1024→48** | `[48,5,30,52]` |
| 分布投影 | `1×1×1` 卷积，**48→48** | `[48,5,30,52]` |

两次时间下采样均向上取整，时间长度依次为 **$17\rightarrow9\rightarrow5$**。全部 6 个块编码完成后，沿时间维拼接得到 `[48,30,30,52]`，再按 `token_drop=3` **从整段末尾丢弃 3 个时间位置**，得到 `[48,27,30,52]`（丢弃的部分对应复制的 12 个末帧）。

随后拆分为 $\mu$ 和 `log_var`，各为 `[24,27,30,52]`；从后验分布采样得到 latent，再按通道标准化。

### 3.2 Decoder：跟踪一个 latent 窗口

先对完整 latent **撤销标准化**，再按 **7 个时间位置一窗、每次前进 5 个位置**解码，相邻窗口重叠 2 个位置。下面跟踪其中一个 `[24,7,30,52]` 的窗口；其视频 token 数和隐藏维度分别为：

$$
N=7\times30\times52=10920,\qquad D=32\times64=2048.
$$

| 顺序 | 模块与操作 | 输出形状 |
|---|---|---|
| 输入 | 撤销标准化后的 latent 窗口 | `[24,7,30,52]` |
| 入口 | `1×1×1` 卷积，**24→24** | `[24,7,30,52]` |
| 展平 | 每个时空位置转为一个 token | `[10920,24]` |
| 特征投影 | Linear，**24→2048** | `[10920,2048]` |
| 附加 token | 追加 **4 个 register token + 1 个初始为零的 token** | `[10925,2048]` |
| 主体 | Transformer block ×36，3D RoPE | `[10925,2048]` |
| 出口 | LayerNorm → Linear，**2048→3072** | `[10925,3072]` |
| 去除附加 token | 保留视频 token | `[10920,3072]` |
| 像素重排 | 每个 token 展开成 **`4×16×16` RGB 块** | `[3,28,480,832]` |

出口将每个视频 token 投影为 **$3072=3\times4\times16\times16$** 个值，再重排成一个 `4×16×16` RGB 块。因此，一个窗口先得到 `[3,28,480,832]`，随后还要做时间裁剪和窗口融合。

#### 时间裁剪与整段拼接

每个窗口输出的 28 帧先分成前 **20 帧**和后 **8 帧**，两部分各裁掉开头 3 帧，留下 **17 帧主体 + 5 帧重叠区域**。

27 个 latent 时间位置共形成 **5 个窗口**。从 0 开始计数，窗口范围依次为 `0-6`、`5-11`、`10-16`、`15-21`、`20-26`。每窗保留 22 帧，相邻窗口融合重叠的 5 帧，最终得到：

$$
5\times22-4\times5=90\text{ 帧}.
$$

融合后的形状为 `[3,90,480,832]`。再裁掉本例额外补入的末尾 9 帧，即恢复为 `[3,81,480,832]`。

这也解释了开头的压缩比问题：如果以实际送入编码流程的 90 帧为分子，元素压缩比约为 106.67:1；如果以原始有效内容的 81 帧为分子，则是 96:1。两种口径都低于表中的标称 128:1，比较时需要说明是否计入补帧。

### 3.3 下采样与像素展开

| 操作 | 具体实现 | 形状变化 |
|---|---|---|
| **空间下采样** | 右、下各反射补 1 → `3×3×3` 因果卷积，步长 `(1,2,2)` | $H,W$ 各减半；$C,T$ 不变 |
| **时空下采样** | 右、下各反射补 1 → `3×3×3` 因果卷积，步长 `(2,2,2)` | $H,W$ 各减半；$T\to\lceil T/2\rceil$；$C$ 不变 |
| **像素展开** | Linear → 时空重排 | 每个视频 token 输出一个 `4×16×16` RGB 块 |

**下采样顺序：**空间 → 时空 → 时空 → 空间，分别位于前四级末尾。两种下采样中的时间卷积都在左侧补 2 个零位置。

#### 残差块、归一化与 Attention

- **残差块：**主分支执行两组“GroupNorm → SiLU → `3×3×3` 因果卷积”，再加 shortcut；通道不同时，shortcut 通过 `1×1×1` 卷积对齐。残差块保持 $T,H,W$。
- **因果编码：**时间卷积只在左侧补零，GroupNorm 按时间位置独立计算。各个 17 帧块独立进入 Encoder。
- **ViT 解码块：**依次执行 RMSNorm → Attention，以及 RMSNorm → 门控 SiLU FFN；两个分支分别经过可学习缩放后加回残差，保持 `[N,2048]`。
- **Attention 范围：**发布配置中的 ViT Decoder 为非因果结构，可以同时关注当前窗口内的各个时间位置。

## 4. LTX-2.5：同一个 latent，为什么有两种 Decoder？

LTX-2.5 的视频 VAE 采用**因果 3D CNN Encoder**，提供两种 Decoder：**非因果 3D CNN 解码器**和**非因果 NA Transformer 扩散解码器**。两者使用相同的 latent 空间，时间压缩倍率为 **8**，空间高宽各压缩 **32** 倍，latent 通道数为 **128**。

同样以 **81 帧、480×832** 的 RGB 视频为例，形状统一写作 `[C,T,H,W]`，省略 `B=1`：

**整段视频：**`[3,81,480,832]` → **latent：**`[128,11,15,26]` → **重建视频：**`[3,81,480,832]`。

$$
T_z=1+\frac{81-1}{8}=11,\qquad H_z=\frac{480}{32}=15,\qquad W_z=\frac{832}{32}=26.
$$

下面跟踪整段视频的 forward 过程。分块与重叠融合属于另外的执行策略，不将视频预先视为 11 个独立编码、解码的小块。

### 4.1 Encoder：跟踪整段 81 帧视频

入口先做 **4×4 空间 patchify**：将每帧相邻的 16 个像素位置重排到通道维，时间长度不变。随后经过**空间 → 时间 → 时空 → 时空**四级下采样。

| 顺序 | 模块与操作 | 输出形状 |
|---|---|---|
| 输入 | RGB 视频 | `[3,81,480,832]` |
| Patchify | 空间 `4×4` 重排，**3→48** | `[48,81,120,208]` |
| 入口 | `3×3×3` 因果卷积，**48→128** | `[128,81,120,208]` |
| 第一级 | 残差块 ×4，128 通道 → **空间下采样，128→256** | `[256,81,60,104]` |
| 第二级 | 残差块 ×6，256 通道 → **时间下采样，256→512** | `[512,41,60,104]` |
| 第三级 | 残差块 ×4，512 通道 → **时空下采样，512→1024** | `[1024,21,30,52]` |
| 第四级 | 残差块 ×2，1024 通道 → **时空下采样，1024→1024** | `[1024,11,15,26]` |
| 瓶颈 | 残差块 ×2，1024 通道 | `[1024,11,15,26]` |
| 出口 | PixelNorm → SiLU → 因果卷积，**1024→129** | `[129,11,15,26]` |

三次时间下采样均保留首帧对应的位置，时间长度依次为：

$$
81\rightarrow41\rightarrow21\rightarrow11.
$$

卷积头输出的前 **128 个通道是 $\mu$**。类似地，再使用逐通道均值和标准差归一化，得到 `[128,11,15,26]`。这里没有 Wan2.1 和 H3 中额外的 `1×1×1` 分布投影卷积。

### 4.2 CNN Decoder：逐级恢复视频

先撤销 latent 的逐通道归一化，再经过卷积残差块和四级上采样，最后通过 unpatchify 恢复 RGB 像素。

| 顺序 | 模块与操作 | 输出形状 |
|---|---|---|
| 输入 | 撤销归一化后的 latent | `[128,11,15,26]` |
| 入口 | `3×3×3` 卷积，**128→1024** | `[1024,11,15,26]` |
| 第一级 | 残差块 ×2，1024 通道 → **时空上采样，1024→512** | `[512,21,30,52]` |
| 第二级 | 残差块 ×2，512 通道 → **时空上采样，512→512** | `[512,41,60,104]` |
| 第三级 | 残差块 ×4，512 通道 → **时间上采样，512→256** | `[256,81,60,104]` |
| 第四级 | 残差块 ×6，256 通道 → **空间上采样，256→128** | `[128,81,120,208]` |
| 第五级 | 残差块 ×4，128 通道 | `[128,81,120,208]` |
| 出口 | PixelNorm → SiLU → `3×3×3` 卷积，**128→48** | `[48,81,120,208]` |
| Unpatchify | 将通道重排成 `4×4` 空间像素块，**48→3** | `[3,81,480,832]` |

时间上采样先将长度翻倍，再删除最前面的一个时间位置，因此每次为 **$T\rightarrow2T-1$**：

$$
11\rightarrow21\rightarrow41\rightarrow81.
$$

该 Decoder 的卷积以**非因果模式**执行，能够利用前后时间位置的信息。

### 4.3 扩散 Decoder：条件特征与像素去噪

它先将 latent 上采样为条件特征 **context**，再以 context 为条件，对像素噪声进行重建，**1 次去噪、直接预测重建视频 $x_0$**。

#### 生成条件特征

官方实现会将最后一个 latent 时间位置额外复制 **2 次**，用于处理邻域 Attention 的末端边界。我们计入这部分临时补帧，并在最后裁掉。

| 顺序 | 模块与操作 | 输出形状 |
|---|---|---|
| 输入 | 撤销归一化后的 latent | `[128,11,15,26]` |
| 边界处理 | 将最后一个 latent 时间位置额外复制 2 次 | `[128,13,15,26]` |
| 入口 | 逐位置 Linear，**128→2048** | `[2048,13,15,26]` |
| 第一级 | NA Block ×4 → **空间上采样，2048→1024** | `[1024,13,30,52]` |
| 第二级 | NA Block ×6 → **时间上采样，1024→512** | `[512,25,30,52]` |
| 第三级 | NA Block ×4 → **时空上采样，512→512** | `[512,49,60,104]` |
| 第四级 | NA Block ×2 → **时空上采样，512→256** | `[256,97,120,208]` |
| 裁剪 | 去掉临时补帧对应的末尾 **16 个时间位置** | `[256,81,120,208]` |

补入的 2 个 latent 时间位置经过 8 倍时间展开，对应 **16 个时间位置**，因此裁剪后为 **$97-16=81$**。得到的 context 已经具有目标视频的时间长度，空间分辨率仍是目标的 **1/4×1/4**。

#### 像素去噪与重建

初始化与目标视频同形状的随机像素噪声。下面跟踪像素特征分支，context 在各个扩散块中作为条件注入。

| 顺序 | 模块与操作 | 输出形状 |
|---|---|---|
| 输入 | 随机像素噪声 $x_t$ | `[3,81,480,832]` |
| Patchify | 空间 `4×4` 重排，**3→48** | `[48,81,120,208]` |
| 入口 | 逐位置 Linear，**48→256** | `[256,81,120,208]` |
| 去噪主干 | Diffusion NA Block ×8，注入 context 和去噪时间步条件 | `[256,81,120,208]` |
| 出口 | RMSNorm → Linear，**256→48** | `[48,81,120,208]` |
| Unpatchify | 将通道重排成 `4×4` RGB 像素块，**48→3** | `[3,81,480,832]` |

最后输出重建视频 $x_0$。

这里要区分三件事：**8 个 Block 是网络深度，1 次去噪是 Decoder 的推理步数，81 则是视频帧数。**“去噪时间步”表示噪声等级，与视频中的时间位置是不同概念。这里的单步解码也不等于整个视频生成模型只运行一次去噪。

### 4.4 NA Attention：局部时空注意力

**NA（Neighborhood Attention）就是邻域注意力。**对于特征图上的每个位置 `(t,h,w)`，只取附近一个三维窗口中的 K、V，与当前位置的 Q 计算 Attention。窗口随查询位置滑动，相邻窗口重叠。

例如 **`3×7×7`** 窗口，在非边界处覆盖**前一个、当前、后一个时间位置**，每个时间位置取 **7×7** 个空间格点。因此，每个查询、每个注意力头关注 **$3\times7\times7=147$** 个位置，包括自身。

| 阶段 | 特征通道 | Attention 头数 | 每头维度 | 窗口：时间 × 高 × 宽 | 每头关注的位置数 |
|---|---:|---:|---:|---|---:|
| 第一级 | 2048 | 32 | 64 | `3×7×7` | 147 |
| 第二级 | 1024 | 16 | 64 | `3×7×7` | 147 |
| 第三级 | 512 | 8 | 64 | `3×5×5` | 75 |
| 第四级 | 512 | 8 | 64 | `3×5×5` | 75 |
| 第五级：像素去噪 | 256 | 4 | 64 | `11×11×11` | 1331 |

所有阶段的每头维度都是 **64**，头数为 **$C/64$**。窗口大小按**所在层的特征格点**计算；NA 本身保持 `[C,T,H,W]`，上采样由另外的模块完成。

普通 NA Block 依次执行：

```text
RMSNorm -> 三维 NA Attention -> 加残差
RMSNorm -> SwiGLU MLP        -> 加残差
```

Q、K 使用每头 RMSNorm 和三维 RoPE；MLP 隐藏维度为 **4C**。第五级的 Diffusion NA Block 额外注入 context，并通过去噪时间步调制特征。

这些 Attention 都是**非因果的**，允许关注后续时间位置。到达边界时，窗口向有效区域内平移以保持大小，例如时间窗口为 3 时，首位置关注 `0、1、2`。

### 4.5 上下采样与时间边界

| 操作 | 具体实现 | 形状变化 |
|---|---|---|
| **空间 Patchify** | 将每帧 `4×4` 像素块重排到通道维 | $H,W$ 各除以 4；$C$ 乘以 16；$T$ 不变 |
| **空间下采样** | 因果卷积 → 空间重排到通道；加重排、分组平均得到的 shortcut | $H,W$ 各减半；$T$ 不变 |
| **时间下采样** | 复制首帧 1 次 → 因果卷积与时间重排；加 shortcut | $T\rightarrow(T+1)/2$；$H,W$ 不变 |
| **时空下采样** | 复制首帧 1 次 → 因果卷积与 `2×2×2` 联合重排；加 shortcut | $T\rightarrow(T+1)/2$；$H,W$ 各减半 |
| **CNN 上采样** | 卷积生成所需通道 → 通道重排到指定时空维度 | 指定轴放大 2 倍；时间放大后删除最前面 1 帧 |
| **NA Decoder 上采样** | Linear 生成所需通道 → 通道重排到指定时空维度 | 指定轴放大 2 倍；时间放大后删除最前面 1 帧 |
| **空间 Unpatchify** | 将通道重排回每帧的 `4×4` 像素块 | $H,W$ 各乘以 4；$C$ 除以 16；$T$ 不变 |

下采样中的主分支先通过卷积调整通道，再将局部时空位置并入通道维；shortcut 则对输入做同样的重排，并通过分组平均匹配输出通道。时空采样采用联合重排。

#### 残差块、归一化与分块

- **CNN 残差块：**主分支主要执行两组“PixelNorm → SiLU → `3×3×3` 卷积”，再加 shortcut，保持 $T,H,W$。
- **PixelNorm：**在每个时空位置上，沿通道维做 RMS 归一化。
- **时间边界：**Encoder 的因果卷积通过复制首帧完成左侧时间填充；含时间下采样的重排模块还会额外复制首帧 1 次。Decoder 则在时间展开后删除前导帧，使整体长度满足 **$T_{\mathrm{out}}=8(T_z-1)+1$**。
- **分块执行：**LTX 支持带重叠区域的 tiling。这里的 **$81=1+10\times8$** 表示时间压缩关系；实际解码需要保留跨时间上下文，不能将 11 个 latent 时间位置分别独立解码后直接拼接。

## 5. FLUX 3：用邻域 Attention 完成编码和解码

FLUX 3 Action 的视频 VAE 采用**因果 NA Transformer Encoder + 非因果 NA Transformer Decoder**，时间压缩倍率为 **4**，空间高宽各压缩 **32** 倍，latent 通道数为 **96**。

同样以 **81 帧、480×832** 的 RGB 视频为例，形状统一写作 `[C,T,H,W]`，省略 `B=1`：

**整段视频：**`[3,81,480,832]` → **latent：**`[96,21,15,26]` → **重建视频：**`[3,81,480,832]`。

$$
T_z=1+\frac{81-1}{4}=21,\qquad H_z=\frac{480}{32}=15,\qquad W_z=\frac{832}{32}=26.
$$

### 5.1 Block 与 Attention

FLUX 3 的 VAE 也使用了 Neighborhood Attention，统一使用 **`5×5×5`** 窗口，还加了 QK Norm 与三维 RoPE；**Encoder 使用时间因果 Attention，Decoder 使用非因果 Attention**。

| 特征通道 | Attention 头数 | 每头维度 | 窗口：时间 × 高 × 宽 |
|---:|---:|---:|---|
| 256 | 4 | 64 | `5×5×5` |
| 512 | 8 | 64 | `5×5×5` |
| 1024 | 16 | 64 | `5×5×5` |
| 2048 | 32 | 64 | `5×5×5` |

单层 NA 中，Encoder 在时间上只关注**当前位置及最多前 4 个位置**；Decoder 在非边界处关注**前 2 个、当前、后 2 个位置**，边界处将窗口向序列内部平移。单帧输入使用 **`5×5` 二维 NA**。

### 5.2 实际分块与上下文

**编码分块：**按 **45 帧一块、每次前进 44 帧**执行，相邻块重叠 1 帧，各块独立进入 Encoder。对于本文的 81 帧输入，会先复制末帧，将 **81 帧补到 89 帧**：

```text
第 1 块：第 1～45 帧
第 2 块：第 45～89 帧
```

每块编码得到 **12 个 latent 时间位置**。保留首块全部输出，后续块丢弃首个 latent 时间位置，再拼接并按原视频长度裁剪：

$$
12+(12-1)=23
\quad\longrightarrow\quad
\text{保留前 }21\text{ 个时间位置}.
$$

### 5.3 Encoder：跟踪一个 45 帧视频块

入口按 **`1×4×4`** 划分像素块并投影到 256 通道，实现为 kernel 和 stride 均为 `1×4×4` 的 Conv3d。随后进行三次空间合并，再在低空间分辨率上完成两次时间合并。

| 顺序 | 模块与操作 | 输出形状 |
|---|---|---|
| 输入 | 当前视频块 | `[3,45,480,832]` |
| 入口 | `1×4×4 Conv3d`，步长 `(1,4,4)`，**3→256** | `[256,45,120,208]` |
| 第一级 | NA Block ×1，256 通道 → **空间合并，256→512** | `[512,45,60,104]` |
| 第二级 | NA Block ×4，512 通道 → **空间合并，512→1024** | `[1024,45,30,52]` |
| 第三级主干 | NA Block ×8，1024 通道 → **空间合并，1024→2048** | `[2048,45,15,26]` |
| 第一次时间压缩 | 附加 NA Block ×1 → **时间合并，45→23** | `[2048,23,15,26]` |
| 第四级主干 | NA Block ×8，2048 通道 | `[2048,23,15,26]` |
| 第二次时间压缩 | 附加 NA Block ×1 → **时间合并，23→12** | `[2048,12,15,26]` |
| 出口 | 逐位置 Linear，**2048→192** | `[192,12,15,26]` |

空间压缩由入口的 4 倍和三次 2 倍空间合并组成：

$$
4\times2\times2\times2=32.
$$

时间长度则依次为：

$$
45\rightarrow23\rightarrow12.
$$

出口沿通道拆成两组，各为 `[96,12,15,26]`，只取前一组作为 **$\mu$**。随后对 $\mu$ 使用模型保存的逐通道均值和标准差归一化。

### 5.4 Decoder：逐级恢复视频

先撤销 latent 的逐通道归一化，再通过 Linear 投影、NA Block 和时空展开，恢复 RGB 视频。形状统一为 `[C,T,H,W]`，省略 batch 维。

| 顺序 | 模块与操作 | 输出形状 |
|---|---|---|
| 输入 | 撤销归一化后的 latent | `[96,21,15,26]` |
| 入口 | 逐位置 Linear，**96→2048** | `[2048,21,15,26]` |
| 第一级时间展开 | NA Block ×8 → **时间展开，21→41** → NA Block ×1 | `[2048,41,15,26]` |
| 第一级空间展开 | **空间展开，2048→1024** | `[1024,41,30,52]` |
| 第二级时间展开 | NA Block ×8 → **时间展开，41→81** → NA Block ×1 | `[1024,81,30,52]` |
| 第二级空间展开 | **空间展开，1024→512** | `[512,81,60,104]` |
| 第三级 | NA Block ×4 → **空间展开，512→256** | `[256,81,120,208]` |
| 第四级 | NA Block ×1，保持 256 通道 | `[256,81,120,208]` |
| 出口 | 逐位置 Linear，**256→48** | `[48,81,120,208]` |
| Unpatchify | 将 **48=3×4×4** 个通道重排为 RGB 像素块 | `[3,81,480,832]` |

每次时间展开满足 **$T\rightarrow2T-1$**，因此时间长度为：

$$
21\rightarrow41\rightarrow81.
$$

### 5.5 上下采样与首帧对齐

| 操作 | 具体实现 | 形状变化 |
|---|---|---|
| **入口 Patch Embedding** | `1×4×4 Conv3d`，步长 `1×4×4`，**3→256** | $H,W$ 各除以 4；$T$ 不变 |
| **空间合并** | 拼接 `2×2` 相邻位置：`C→4C` → LayerNorm → Linear **4C→2C** | $H,W$ 各减半；$C$ 翻倍 |
| **时间合并** | 奇数长度时在开头复制首位置 → 两位置拼接 → LayerNorm → Linear **2C→C** → 加两位置的均值 shortcut | $T\rightarrow\lceil T/2\rceil$；$C,H,W$ 不变 |
| **空间展开** | LayerNorm → Linear **C→4C_out** → 重排成 `2×2` 空间位置，其中 `C_out=C/2` | $H,W$ 各翻倍；$C$ 减半 |
| **时间展开** | LayerNorm → Linear **C→2C** → 加输入在通道维复制两份的 shortcut → 重排到时间维 → 删除首位置 | $T\rightarrow2T-1$；$C,H,W$ 不变 |
| **空间 Unpatchify** | 将每个位置的 48 个通道重排为 `3×4×4` 像素块 | $H,W$ 各乘以 4；输出 3 通道 |

**执行顺序：**

- Encoder 第三级：空间合并 → 附加 NA Block → 时间合并；第四级在主干后执行附加 NA Block → 时间合并。
- Decoder 前两级：时间展开 → 附加 NA Block → 空间展开。

**首帧对齐：**编码时通过复制首位置补齐奇数长度，解码时通过删除展开后的首位置恢复对齐。单帧也经过这些模块，但长度仍为 1：

```text
Encoder：1 → 复制成 2 → 合并成 1
Decoder：1 → 展开成 2 → 删除首位置后剩 1
```

两次时间展开后，输出长度为：

$$
T_{\mathrm{out}}=2(2T_z-1)-1=4(T_z-1)+1.
$$

## 6. 把这些结构放在一起，应该怎么比较？

看完逐层形状，再回到最初的问题，几个区别就比较清楚了。

**第一，压缩倍率要和通道数一起看。**4×16×16 描述的是时空分辨率变化，元素压缩比还取决于 latent 通道数。对具体输入，首帧、补帧和裁剪也会影响实际比值。

**第二，VAE latent 和 DiT token 是两层概念。**VAE 决定潜在表示的网格和通道，DiT patchify 决定如何把这个网格组织成 token。少算一步 patchify，就可能把 token 数算错数倍。

**第三，因果性需要分别检查 Encoder 和 Decoder。**Wan2.1 的两端都使用因果卷积；H3、LTX-2.5 和 FLUX 3 的本文配置则使用非因果 Decoder。编码端只能看历史，并不能推出解码端也只能看历史。

**第四，分块执行需要连同上下文一起读。**Wan2.1 依赖各层历史缓存，H3 通过重叠 latent 窗口解码并融合输出，LTX 支持带重叠区域的 tiling，FLUX 的编码块也包含重叠帧。只看到“分块”，还不足以判断哪些输出可以直接拼接。

**第五，Decoder 的结构本身就有很大差异。**H3 将 Transformer 输出直接投影为 RGB 时空块；LTX 除了 CNN Decoder，还提供以 latent 特征为条件的像素扩散 Decoder；FLUX 则用邻域 Attention 配合时空合并与展开。即使 latent 尺寸相近，它们恢复像素的方式也可能完全不同。

实际读一个新模型时，可以先写下这条形状链：

```text
输入视频 [B,3,T,H,W]
    ↓ 首帧处理、补帧与 Encoder
VAE latent [B,C,T_z,H_z,W_z]
    ↓ DiT patchify
视觉 token [B,N,D_patch]
    ↓ DiT 的输入投影
模型隐藏表示 [B,N,D_model]
```

随后单独追踪 Decoder，记录每次时间展开后的裁剪，以及分块之间的缓存或重叠区域。把这些环节对齐，才能解释“同样是 4 倍时间压缩”的两个模型，为什么会得到不同的实际形状和执行过程。
